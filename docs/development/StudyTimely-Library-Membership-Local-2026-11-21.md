## User flow

- Content is visible in existing theme/music/scene pickers, with Free, Plus · free preview, or Plus text labels. Scene labels overlay the thumbnail so they are visible before scrolling through descriptions. No extra navigation, pricing-page dead end or fake purchase button was added.
- Without access: all free items work. Plus music plays only a separate eight-second sample; category playlists and next/automatic advancement use available full tracks. Favorites and saved queues can retain Plus items without granting access. A Plus scene thumbnail can be viewed but never applied. A Plus colour shows its swatch and an inline explanation without changing the applied colour.
- With a trusted active account grant: full tracks/scenes/colour themes are available. A group owner does not grant all members personal library access. Group-atmosphere selectors use the same labels and eligibility rules.
- On expiry, logout, access-check failure or revocation: expanded playback pauses, expanded scene/colour presentation uses a free alternative, and timers continue. Records, favorites and saved presets remain. A restored grant does not auto-play music. No study or ranking credit is generated by media controls.
- Public thumbnails and samples are distinct bounded files. Full expanded audio, full-size scene images and moving-scene files are checked by the Worker, including legacy paths and encoded aliases. Private `/library/full/...` URLs avoid reusing formerly public immutable media caches. Successful protected responses use private/no-store and vary by Cookie. This cannot recall copies downloaded or cached under earlier releases; music remains CC BY 4.0, not exclusive copyright.
- The offline shell contains free full scene posters and public thumbnails; full Plus media and audio samples are not mandatory precache downloads. Basic tools remain available when access checks fail.

## Implementation and later billing integration

- `src/lib/library-access.mjs` is the shared content boundary; `server/learning-features.mjs` resolves the `library` discovery field and trusted access from the authenticated account's existing `community_entitlements.expires_at`, bounded by session expiry. UI preferences/query parameters cannot create a grant.
- One shared library context refreshes on account changes, visibility and a 60-second interval, with local deadline handling. Backend checks each protected request independently. Server failures fail closed while free content stays usable.
- There is no public entitlement-writing endpoint. Later payment work must provision/revoke the existing grant from verified, idempotent provider events associated with the correct account. The initial membership model treats the library as part of the same trusted subscription bundle as advanced learning/group access; splitting SKUs would require a further entitlement-schema design.
- Before paid launch: choose product/period/price, implement checkout and subscription management, signature-verified durable callbacks and lifecycle reconciliation; define the free-preview transition/end date explicitly, validate real authenticated sandbox purchases and cancellation/refund/renewal behavior, and update purchase terms and UI. Turning preview off is **not** done as part of this local work. No price or billing button is invented.
- Keep original music attribution/licences and natural-sound licences. Public terms now describe the actual content boundary and no-charge preview accurately; no payment is offered.
