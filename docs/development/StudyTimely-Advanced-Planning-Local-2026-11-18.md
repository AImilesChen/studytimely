# Advanced study planning — local core implementation

18 November 2026. User-authorized development of the proposed first core round (unified plans, scheduling and execution/feedback). Local only: uncommitted, unpushed, undeployed. Production/package remains V2.31.1; no production resources, subscription grants or payments changed.

## Workflow

The existing /study-planner now wraps the original basic task planner in Today / Week / Plans. Basic task editing, task-linked timers, calculator drafts, task filters and daily task summaries remain. Plans supports custom/exam/course/assignment goals and optional existing exam links. Tasks can be linked from the existing task collection, created explicitly, or created from current leaf syllabus topics. Reusing a source topic reuses the existing linked task. Remaining work, earliest dates and prerequisites are separate from recorded learning.

Available time accepts multiple weekly study windows or a reviewed import of existing study-routine windows, an IANA zone, focused daily limit, preferred focus length, minimum task segment, break length and daily buffer. Routine fixed commitments/breaks, date exceptions and preserved sessions are subtracted; overlapping study windows are unioned. Rest days override extra windows. Blank calendar time is not assumed available. Focus windows are separated by breaks; multiple task segments can share a focus window. Missing or ambiguous clock-change endpoints are skipped with warnings.

Generate schedule previews 7/14/30 days, all open tasks or one goal. It uses task/goal/linked-exam deadlines, priority, earliest start and prerequisites, and subtracts already-preserved future allocations from remaining work. Unknown estimates, zero-but-unfinished work, removed or incomplete prerequisites and unplaced work have explicit reasons. These are deterministic heuristic results, not proof of global optimality. A later-deadline task outside the horizon is distinguished from a current-horizon deadline warning.

Apply recomputes from the same recipe and snapshot, rejects changed data or a preview older than 15 minutes, and rejects proposed times already in the past. It replaces only scoped future unlocked planned sessions, protecting the active linked timer and other retained sessions. The last generation has a bounded undo record; later edits invalidate undo. Existing original tasks are not copied per session. Locked sessions, fixed commitments and recorded time are not rewritten.

Week displays dated session cards, fixed routine commitments/breaks, a task sidebar, pending work and up-to remaining focus capacity. Small screens use a stacked agenda. Session details allow starting the existing Study Timer, locking/unlocking, skipping, moving through an explicit form, and checkout feedback. Moving checks availability, overlaps, earliest date, exact linked exam deadline and prerequisite allocations. There is no drag/drop interaction in this core version; explicit controls provide the movement path. The goal archive action hides the goal with a retained deletion marker and leaves task/history data; a dedicated archived-goal restore interface is not included.

Timers and saved learning sessions carry an optional planningBlockId; existing task and optional syllabus/topic links are kept through Pomodoro phases and backup validation. Actual recorded time is still produced only by the existing timer engine. Feedback explicitly sets task completion or remaining work; elapsed study never silently completes a task. The plan can then be generated again. A review link opens existing analytics; planned-vs-recorded amounts appear in session detail.

## Data and access

workspace.planning v1 is separate from workspace.plans (syllabus). It validates settings, availability, exceptions, goals, task rules, dated blocks, feedback and the undo record. Workspace actions run through the existing atomic repository with planning revision CAS. Tombstones and deterministic merges preserve concurrent independent item edits; a merged dependency cycle fails rather than silently dropping a relationship. Cloud writes from older clients cannot strip existing plan data.

A same-store advanced-planning-v1 companion key, bound to the workspace epoch, protects planning fields if an older local client rewrites the basic root with an older validator. Root and companion writes share the same IndexedDB transaction. An old-client workspace reset changes the epoch and cannot revive the prior companion. No IndexedDB version/store or D1 migration was added. Backups include the hydrated planning data. The existing 1MiB manual cloud-snapshot limit and backup limits remain.

Current limits: 200 goals, 100 retained availability records, 500 exceptions, 5000 rules/blocks/feedback records per collection, up to 2000 changed blocks per generation/undo and 30 prerequisites per task. Edits preserve availability IDs. These are validation/resource bounds, not paid usage packs. Reaching them fails without overwriting data.

GET /api/learning/features adds planning access alongside analytics, using a separately compiled public preview policy and the existing authenticated trusted entitlement. advancedPlanningPreview=true and expiry0 enable the current free preview without a charge or grant endpoint. Basic planning and existing retained data remain accessible; advanced creation/generation controls check current access. This local computation gate is not DRM; future server-backed paid actions must enforce their own authorization. Planning does not call an AI provider, send task content to an inference service or add remote sync automation.

Detailed public instructions and privacy copy describe the actual workflow, counting, data controls and preview. Planner example/view URLs are noindex, including in an indexable Worker. The example is explicitly read only, generated from separate illustrative data, and never written into personal history.

## Plans detail workspace — 18 November 2026 (latest local revision)

Replaces the fixed three-column goal-card grid. Plans now has a 270px plan list and a flexible selected-plan workspace: goal/deadline, completion and remaining-work summary, upcoming planned time, next-session action, and task rows with remaining estimates, dates/times, arrangement status and direct actions. Only the selected plan's detailed tasks render; all plans remain selectable. Invalid/archived selection falls back to an available plan. No-goal, no-task, fully completed, unknown-estimate, stale-arrangement, running and pending-feedback states are distinct. Sidebar summaries and selected-plan task/session lookups use indexed data instead of repeatedly scanning every historical record for every plan.

Add task, edit task/remaining work, preview arrangements, session details/start/feedback and archive route to the existing actual commands. Editing or giving feedback from Plans retains the Plans view; applying a generated schedule still opens Week. Generation is scoped to the selected plan and opens availability first if no windows exist. Multiple task sessions link to their schedule week. Real starts retain the existing active-timer guard; example starts remain isolated simulations and open their session dialog. A failed simulation does not open an unrelated dialog. Completed task editors retain their selected task and accept its zero remaining estimate.
