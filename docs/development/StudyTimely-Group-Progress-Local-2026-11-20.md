# Group progress — local implementation, 20 November 2026

Implemented the approved progress-and-review plan in the existing application. The established five room destinations, independent timer, activity instance, private tasks/results and account permissions are retained. Publication is recorded separately when verified.

## Behaviour

- Today’s overview: a two-to-one shared-goal card and personal/participation cards, confirmed short durations, percentage/remaining or excess time, current-member contributions and a separate aggregate for other retained records. Unknown totals stay unavailable. Zero and stale/error states have useful actions. Only the owner with participation access can adjust the current daily goal, through the original versioned settings API.
- The next action prioritises room access, a matching running room timer, the member’s pending result and then an appointment. All actions navigate to original controls; opening a view does not start a timer. The existing mounted RoomActivities supplies the recent list and notice; an explicitly scoped navigation request opens the matching existing result form.
- Weekly reports reuse GroupTools with a report-only view. Shared challenge remains in Advanced tools; a report link returns to Group progress. Free preview and retained-read-only access keep the existing server checks. Week changes clear the previous report before fetching. The twelve choices, UTC date range, chart, daily table, attendance and CSV remain functional.
- Three actual synthetic local screenshots sit below the working controls and enlarge in the existing Dialog. They total 173,230 bytes. No image generation, new dependency or external asset was needed.
- The public session planner computes people × study minutes, distinguishes estimates from recorded time, copies the plan and passes a proposed goal into the original creation form. The bounded target survives the existing ten-minute sessionStorage sign-in-return draft. Public explanatory content uses existing routes; no new SEO page was created.
- Existing room totals now include recorded participant count and retained date bounds. One aggregate query supplies these fields, including former-member time. No schema migration or timer-credit change. Private room/invitation/activity HTML robots now agrees with the existing noindex/no-store headers; public landing HTML stays indexable in release mode.
