# Google sign-in setup

The operator will create the Google Cloud project/client personally. No OAuth credentials have been generated by this implementation.

| Console field | Value |
|---|---|
| Dedicated project / app name | StudyTimely |
| App home | `https://studytimely.com/` |
| Privacy policy | `https://studytimely.com/privacy` |
| Terms | `https://studytimely.com/terms` |
| Authorised domain | `studytimely.com` |
| Application type | Web application |
| Client name | StudyTimely production web |
| Authorised JavaScript origin | `https://studytimely.com` |
| Authorised redirect URI | `https://studytimely.com/api/auth/google/callback` |
| Requested scopes | `openid`, `email` only |
| Public support contact | `support@studytimely.com` |

Use the actual operator-owned account for developer-contact fields; where Google restricts the support-address dropdown, choose an address the operator controls. No Drive, calendar, contacts, profile-photo permission, offline access or refresh token is required. For scopes beyond basic identity, an External audience in Testing is restricted to listed test users. Google documents an exception for basic identity scopes such as this app's `openid email`; therefore Testing alone does not prove sign-in is blocked. Inspect the actual branding/domain state and verify the real sign-in flow before declaring availability. Do not enable billing or another project's APIs merely to follow this checklist.

Keep the client secret out of chat, screenshots, Git and frontend code. Place both values in ignored `app/.dev.vars` on the operator's computer:

```dotenv
GOOGLE_CLIENT_ID="YOUR_WEB_CLIENT_ID"
GOOGLE_CLIENT_SECRET="YOUR_WEB_CLIENT_SECRET"
```

This is a format example, not a usable credential. The existing `AUTH_HMAC` Secret must be preserved on Cloudflare; do not replace it with a sample key. The production credentials must also be installed as Cloudflare Secrets before deployment; a local file alone does not configure production.

Community moderation requires a separately authorised operator Google email in the encrypted `COMMUNITY_ADMIN_EMAILS` setting. This grants access to reported content and moderation actions. Do not default to the first account or infer the public support inbox is a Google login. Chat stays closed until the moderator allowlist is configured.

After local credentials are present, the remaining developer work is production backup/migrations, encrypted configuration, deployment and real login/permission verification. The current online policy still reflects V1.1.2; the V2 candidate policies must be published with the V2 release and assessed in the actual Google console. Configuration is not proof of Google approval or a completed end-to-end sign-in.

Official references: [OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect), [Web server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [OAuth production readiness](https://support.google.com/cloud/answer/13463073).
